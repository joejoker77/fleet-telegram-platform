# M5.10 — Workspace scopes: порядок на главной + области каталогов

Прямой запрос Vitaliy (msg 2960, 2026-06-12): «на главной видно всю домашнюю
директорию… вся засрана мусором… сделать рабочей директорией в UI какую-то
одну… доступ к корню домашней директории — но при необходимости… по умолчанию
прятать мусор». Сюда же — архитектурный фундамент двуязычности ru/en (msg 2960,
второй пункт). Pilot: vitaliy only (как весь M1+). Концепция трёх областей
одобрена msg 2963; этот док — детали на ревью ПЕРЕД кодом.

## Диагноз (почему сейчас плохо)

Главный экран Mini App = `GET /fs/tree` → **рекурсивный** дамп
`~/.claude` (fs-routes.ts: `tenantRoot = <home>/<user>/.claude`). Это
каталог РАНТАЙМА Claude Code: backups, cache, channels, checkpoints,
file-history, paste-cache, projects, shell-snapshots, telemetry,
7× `settings.json.bak*`… Артефакты юзера (agents/, commands/, skills/)
тонут в этом шуме, а настоящая рабочая зона — `~/work` и проекты
M5.7-сессий — Mini App **не видна вообще**.

## Модель: три области (scope) у одного FileTree

| scope | корень | что это | по умолчанию |
|---|---|---|---|
| `project` 📁 Проект | каталог **активной сессии**: `~/work` (default) или `~/work/projects/<name>` | рабочая зона юзера — «создавай наработки здесь» | **да** — главный экран |
| `artifacts` 🧩 Артефакты | `~/.claude`, но **белый список** верхнего уровня | то, что юзер реально правит: `agents/`, `commands/`, `skills/`, `CLAUDE.md`, `settings.json` | вкладка |
| `home` 🗂 Всё | `~` (вся домашка) | экспертный режим «при необходимости» | только явным переключением |

Переключатель — сегмент-контрол над деревом. Выбор запоминается в
`localStorage`, но при старте всегда `project` (главная = чистая рабочая
зона, как просил Vitaliy).

Корень `project` cp-api определяет сам по активной сессии (та же логика,
что session-routes M5.7: `name === "default" ? ~/work : ~/work/projects/<name>`)
— клиент не передаёт путей-корней, только имя scope.

### Скрытие мусора (server-side, с тумблером)

В scope `project` и `home` сервер по умолчанию НЕ отдаёт «мусорные» классы:

- служебные каталоги: `.trash`, `node_modules`, `.git`, `dist`, `build`,
  `.venv`, `venv`, `__pycache__`, `.cache`, `.npm`, `.local`, `.config`*
- dotfiles/dot-каталоги в scope `home` на верхнем уровне (`.bashrc`,
  `.ssh`, `.claude`…) — именно они и есть «засранность» корня домашки;
- `*.log`, `*.tmp`.

\* список — константа `HIDE_CLASSES` в fs-routes, не настройка юзера.

Тумблер «👁 показать скрытое» в UI → `?all=1` → сервер отдаёт всё
(кроме `node_modules/.git` содержимого — см. lazy ниже, раскрываются
как обычные каталоги по клику, но это редкий экспертный случай).
В scope `artifacts` скрывать нечего — белый список и так курирует.

### Lazy-листинг вместо рекурсивного дампа

Сейчас walk рекурсивно обходит всё дерево — для `~` это тысячи записей
(node_modules, .cache…) в одном ответе. Меняем контракт:

```
GET /fs/tree?scope=project|artifacts|home&dir=<rel>&all=1?
→ { root: "<подпись корня>", dir: "<rel>", entries: [ {name,type,size} ] }
```

**Один уровень за вызов.** FileTree грузит детей при раскрытии каталога
(▸ → fetch → ▾, спиннер на строке). Совместимость: **без параметров**
`/fs/tree` отвечает по-старому (рекурсивный дамп `.claude`) — старый
бандл Mini App не ломается в окне деплоя; уберём старую ветку после M5.10.

### Чтение/запись файлов в областях

`GET/PUT /fs/file` получают тот же параметр `scope` (default `artifacts` =
сегодняшнее поведение, обратная совместимость). Разрешение пути:
`safeResolve(scopeRoot, rel)` + `assertRealInside(scopeRoot, abs)` — те же
two-step хелперы fs-safety, только корень выбирается из **фиксированного
серверного словаря** областей. Юзер не может передать собственный корень —
только имя scope; всё разрешённое лежит внутри домашки тенанта.

Это сразу чинит давний разрыв: `~/work/CLAUDE.md` и `~/work/.mcp.json`
становятся редактируемыми из IDE (scope=project), раньше Mini App их
не видел в принципе.

## Безопасность / инварианты

- **Траст-класс не меняется (boundary-1, ADR-004):** тенант смотрит и
  правит СВОЮ домашку. `~/.claude` уже был доступен на запись через
  fs-routes; `~/work`/`~` — та же граница (бот и так пишет туда шеллом).
  Containment, не pre-screening: PUT по-прежнему без judge-гейта, с
  builtin-advisory + аудит `fs.write` (добавляем в payload `scope`).
- `settings.json` security-ключи — по-прежнему под WP7 settings-guard /
  agentshield (не наша поверхность).
- Никаких новых root-компонентов, под/образ не трогаем — только cp-api
  (fs-routes) + Mini App.
- MAX_FILE 1 MiB и лимиты как были.
- Rollback: `git revert <commit>` + `podman restart cp-api` + dist copy.
  Параметрless-контракт сохранён → старый клиент со старым API совместимы
  в любом порядке отката.

## Фундамент i18n (ru/en) — закладываем сейчас, не переписываем потом

Принцип: **ни одна новая строка UI не хардкодится в JSX** — всё через
словарь. Старые экраны мигрируем попутно (механическая замена), не
блокируя M5.10.

1. **Mini App**: модуль `src/i18n.ts` —
   `t("ключ")` + словарь `ru` (заполнен сейчас) / `en` (ключи те же,
   заполним на этапе двуязычности). Локаль: `initDataUnsafe.user.language_code`
   → override-переключатель в UI (localStorage). Пока словарь en пуст —
   fallback на ru, переключатель скрыт.
2. **Ошибки API**: к человеческому `error` добавляем стабильный
   `code` (`"file_too_large"`, `"bad_path"`…). Клиент переводит по code,
   незнакомый code → показывает серверный текст. Вводим оппортунистически:
   новые маршруты — обязательно, старые — по мере касания.
3. **Компиляторы билдеров** (`builders/compile.ts`): сигнатура получает
   `lang: "ru" | "en"` (сейчас всегда `"ru"`), шаблонные строки — из
   словаря компилятора. M5.9 WorkflowBuilder пишется так с первого дня.
4. **Язык чата бота** (отвечает Claude, не UI) — отдельный поздний этап:
   колонка `lang` в users + инъекция в CLAUDE.md тенанта. В M5.10 НЕ
   входит, зафиксировано чтобы архитектура не мешала.

## UI-изменения (Mini App)

- `App.tsx`: сегмент-контрол областей над деревом (📁 / 🧩 / 🗂);
  состояние `{scope, dir-кэш}`; кнопка «👁».
- `FileTree.tsx`: переход с пред-построенного дерева на lazy-ноды
  (fetch детей на раскрытие, кэш на время экрана, pull-to-refresh
  сбрасывает кэш).
- `FileView` / билдеры: прокидывают `scope` в `fsFile`/`fsPut`
  (билдеры всегда пишут в `artifacts` — их пути `agents/…`,
  `commands/…` остаются как есть).
- Все новые строки — через `t()`.

## Деплой / приёмка

1. cp-api: `podman restart cp-api`; Mini App: vite build + dist copy.
   Под/образ НЕ трогаем (ребилд M5.8 — независимый хвост).
2. `install/m5.10-accept.mjs` (тот же auth-каркас):
   - `/fs/tree` без параметров → старый формат (back-compat);
   - `scope=project` → корень = каталог активной сессии, `node_modules`
     и `.trash` отсутствуют, с `all=1` — присутствуют;
   - `scope=artifacts` → только белый список на верхнем уровне;
   - `scope=home&dir=work` → один уровень, без рекурсии;
   - `scope=evil`, `dir=../../etc` → 400;
   - `PUT scope=project path=CLAUDE.md` round-trip + аудит со scope.
3. Ручной тест: главная открывается на 📁 Проект и выглядит чисто;
   создание файла в проекте; 🗂 Всё показывает домашку лениво.

## Открытые вопросы (на ревью)

1. **Lazy-листинг по уровням** (`?dir=` на каждое раскрытие) вместо
   рекурсивного дампа — ок? Альтернатива «рекурсивно, но с hide-списком»
   проще в UI, но `home`-scope всё равно отдаст тысячи записей.
   Предложение: lazy.
2. **`home`-scope: read-write или read-only?** Предложение: **read-write**
   (граница та же, бот и так пишет в домашку; запрет ничего не защищает,
   а юзеру мешает). Если хочешь страховку от случайных правок — могу
   сделать read-only с per-file разблокировкой, но это UI-трение.
3. **Прятать dot-файлы в `home` по умолчанию** (показывать по 👁) — ок?
   Предложение: да — именно они и есть основной «мусор» корня.
