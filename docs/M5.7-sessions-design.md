# M5.7 — SessionsManager: именованные сессии/проекты + переключение

Закрывает последний формальный пункт гейта M5 («мультисессии работают»,
[06-build-overview](../../upgrade/06-build-overview.md) / дизайн
[10-authoring-miniapp-ide](../../upgrade/10-authoring-miniapp-ide.md)).
Pilot: vitaliy only (как весь M1+).

## Модель

- **Сессия = именованный проект**: каталог `~/work/projects/<name>` + история
  Claude Code этого каталога. История у Claude Code привязана к cwd
  (`~/.claude/projects/<slug-пути>`), поэтому смена cwd = смена истории;
  `claude --continue` поднимает последний разговор каталога. Ничего
  изобретать не нужно — модель сессий уже в продукте.
- **Default-сессия** = `~/work` (имя `default`, есть всегда, не удаляется).
- **Ровно один живой `claude` на тенанта.** Телеграм-плагин — синглтон по
  bot-токену (инцидент 2026-06-01: второй инстанс отбирает getUpdates у
  первого). Поэтому переключение = пересоздание pane с новым cwd, а НЕ
  параллельные инстансы. Параллельные headless-сессии — вне скоупа (M13+).
- **DB**: таблица `sessions` уже в схеме 0000 (`session_name`, `state`
  active/idle/closed, `claude_session_id`, timestamps). `claude_session_id`
  заполнит M5.8 (checkpoints); здесь он остаётся NULL.

## Механика переключения — control-файл, БЕЗ нового root-хелпера

Рассмотрен и отвергнут вариант «cp-sessiond по образцу cp-secretd +
`podman exec`»: новая привилегированная поверхность (root-юнит + exec в
namespace тенанта) ради действия, которое целиком лежит ВНУТРИ границы
тенанта. По ADR-004 гейт нужен на границе, а не внутри неё.

Принятый путь:

1. **cp-api пишет запрос** `~/.claude/run/session-switch.json`
   (атомарно: tmp + rename; fs-доступ к песочнице у cp-api уже есть —
   тот же канал, что fs-routes):
   `{"id":"<uuid>","action":"switch","name":"<session>"}`.
2. **Супервизор-цикл entrypoint** (уже крутится с шагом 5 с) на каждой
   итерации проверяет файл. Увидев запрос: валидирует имя
   (`^[a-z0-9][a-z0-9-]{0,31}$`, каталог существует под `~/work/projects/`
   либо `default`), затем `tmux respawn-window -k` с
   `cd <dir> && exec $CLAUDE_CMD --continue`. Запуск claude выносится в
   общую функцию `launch_claude()` (boot и switch используют один код).
   Результат пишет в `~/.claude/run/session-switch.result.json`
   (`{"id":…,"ok":…,"error":…}`), запрос удаляет.
   Краткий обрыв канала при respawn покрыт существующим
   `CHAN_FLAP_GRACE=60s` — супервизор сам выполняет respawn и не считает
   это смертью.
3. **Маркер активной сессии** `~/.claude/run/active-session` (имя).
   Читается: (а) при буте пода — рестарт возвращает бота в активный
   проект, не в default; (б) cp-api — для `GET /sessions`.
4. **Telegram-паритет**: `/opt/platform/session-ctl switch <name>` — тот же
   код-путь (скрипт пишет тот же запрос-файл; выполняет супервизор).
   Бот может переключить сам себя по просьбе пользователя в чате;
   «suicide-switch» безопасен, т.к. исполнитель — супервизор, не claude.

## API (cp-api, `session-routes.ts`)

- `GET /sessions` — список: DB reconciled с каталогами + active-маркер.
  Каталог без строки в DB → строка создаётся (self-heal); строка без
  каталога → state=closed.
- `POST /sessions {name}` — валидация имени (regex выше), `mkdir -p`
  каталога, insert (state=idle). 409 при дубле.
- `POST /sessions/:id/switch` — пишет запрос-файл, поллит result-файл
  (до 90 с), по ok: active→idle для прежней, state=active для новой,
  обновляет active-маркер ответом супервизора. 504 при таймауте.
- `DELETE` — НЕ в этом этапе (никакого удаления данных).
- Каждая операция — в аудит-цепочку (механизм уже есть).
- Авторизация: тот же JWT + tenant-binding, что fs-routes.

## Mini App

- Экран **SessionsManager**: список сессий (badge active,
  `last_message_at`), форма создания, кнопка switch с confirm
  («переключение прервёт текущую работу бота в активной сессии»).
- Вход с новой иконки в шапке App.tsx (рядом с Аппрувами/Live).

## Безопасность / инварианты

- Имя — whitelist-regex; путь собирается строго как
  `~/work/projects/<name>` (resolve + prefix-check, как в fs-safety).
- Запрос-файл живёт в песочнице тенанта; писать его могут cp-api (от
  имени тенанта) и сам тенант — эскалации привилегий нет: всё, что
  достижимо через switch, тенант и так может сделать руками в tmux.
- Никаких новых root-юнитов/таймеров/LLM-вызовов; teardown-список не растёт.
- Rollback одной командой: `git revert` коммита + rebuild image
  (обработчик уходит из entrypoint), cp-api перезапуск без session-routes.

cp-api `session-routes.ts` (wired в index.ts, 501-стаб `/sessions` снят),
miniapp SessionsManager (🗂 в шапке), `install/m5.7-accept.mjs`.
Typecheck api+miniapp OK, vite build OK, bash -n OK.

1. **Image rebuild + pod restart** (убивает текущую сессию бота — ожидаемо):
   ```
   bash /home/vitaliy/work/fleet-platform/runtime/install/m2.1-build-image.sh
   systemctl restart claude-pod@vitaliy
   ```

   (тег образа — `claude-user:latest`, его ждёт `claude-pod-run`; НЕ
   `fleet-runtime` — ошибка первой редакции этого дока)
2. **cp-api deploy** (как обычно для cp-api: рестарт сервиса, поднимающего
   apps/api через tsx; настроек/миграций НЕ нужно — таблица sessions есть с M1):
   ```
   podman restart cp-api
   ```
3. **Miniapp deploy**: `dist/` уже собран в репо-checkout:
   ```
   cp -r control-plane/apps/miniapp/dist/* /var/www/miniapp/dist/
   ```
4. **Приёмка, фаза A** (безопасная, бота не трогает):
   ```
   podman run --rm --network host --secret cp_bot_token -v /home/vitaliy/work/fleet-platform/control-plane:/cp:ro -w /cp -e BOT_TOKEN_FILE=/run/secrets/cp_bot_token docker.io/library/node:22-alpine node install/m5.7-accept.mjs
   ```
5. **Приёмка, фаза B** (та же команда + `-e DO_SWITCH=1`; ДЕСТРУКТИВНО —
   дважды респавнит pane клода; гонять, когда бот idle). Спот-чек cwd:
   `podman exec claude-vitaliy tmux display-message -p -t claude '#{pane_current_path}'`.
6. Ручной тест: переключение из Mini App (🗂) + `session-ctl list/switch`
   из чата бота.

**Rollback (одна команда на слой):** `git revert <commit>` + повтор шага
соответствующего слоя (image rebuild / cp-api restart / cp dist). До
ребилда образа новые маршруты cp-api просто отвечают 504 по switch
(супервизор не читает request-файл) — деградация мягкая.
