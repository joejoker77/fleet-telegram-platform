## Почему НЕ нативные чекпоинты Claude Code (исследовано 2026-06-12)

Claude Code пишет `~/.claude/file-history/<sessionId>/<hash>@vN` + события
`file-history-snapshot` в jsonl разговора. Проверено на живых данных:
снапшоты покрывают **только правки через инструменты Edit/Write**. Всё,
что бот делает через Bash — git-операции, скрипты, билды, `npm install`,
генерация файлов — в file-history **не попадает вообще**
(`trackedFileBackups` пуст для bash-изменений). Наш бот меняет файлы
преимущественно шеллом → нативный rewind вернул бы разговор, но НЕ файлы.
Плюс формат jsonl/file-history — внутренний, без контракта версий.

Нативный механизм остаётся как есть (TUI `/rewind` в IDE никто не
отключает), но платформенный чекпоинт строим поверх детерминированных
примитивов: **git-снапшот каталога проекта + копия jsonl разговора**.

## Модель

**Чекпоинт = (а) git-коммит рабочего каталога сессии в теневом репо +
(б) копия текущего jsonl разговора + (в) строка метаданных.** Всё — внутри
домашки тенанта (boundary-1, тот же траст что fs-routes/M5.7).

- Теневой репозиторий: `~/.claude/checkpoints/<session>/repo.git`
  (bare, `GIT_DIR` отдельно от worktree). Worktree = каталог сессии
  (`~/work` для default, иначе `~/work/projects/<name>`).
  `git --git-dir=... --work-tree=... add -A && commit` — проектный
  `.gitignore` уважается; `.trash`, `node_modules`, `dist` исключаются
  глобальным excludesFile теневого репо.
- Копия разговора: `~/.claude/checkpoints/<session>/conv/<checkpoint-id>.jsonl`
  — снимок самого свежего jsonl из `~/.claude/projects/<slug-cwd>/`.
  Снимок на живой сессии безопасен: torn-tail у jsonl допустим (это
  append-only лог, оборванная последняя строка игнорируется при resume).
- Метаданные: `~/.claude/checkpoints/<session>/index.json` — массив
  `{id, label, ts, commit, convFile, auto}`. ФС — ground truth (как в
  M5.7: DB только отражает), без новой таблицы. `sessions.claude_session_id`
  заполняем при чекпоинте (sessionId свежего jsonl) — чисто информационно.

**Ограничение (зафиксировать в UI-тексте):** вложенные git-репозитории
внутри каталога сессии (например `~/work/fleet-platform`) снапшотятся как
gitlink — их РАБОЧИЕ файлы защищает их собственный git, а не чекпоинт.
Для default-сессии это норма: у проектов там своя история. MVP это
документирует, не решает.

## Операции

### Исполнитель — супервизор entrypoint для ВСЕХ мутаций (build-решение)

Первая редакция этого дока предполагала, что create делает cp-api напрямую.
На билде решено иначе: **create, rewind и delete чекпоинта исполняет
супервизор** через новую пару control-файлов
`~/.claude/run/session-task.json` / `session-task.result.json`
(`{"id":…,"action":"checkpoint|rewind|ckpt-delete","name":…,"label":…,
"checkpoint":…}`; cp-api поллит результат ≤90 с — контракт switch).
Причины: единственный писатель `index.json` (нет гонок cp-api ↔
session-ctl), файлы гарантированно принадлежат тенанту, git гарантированно
есть в поде (в контейнере cp-api — best-effort apk). cp-api только пишет
запрос, читает `index.json` (read-only) и ведёт аудит.

### create — на живой сессии, без остановки

`POST /sessions/:id/checkpoints {label?}` → задача супервизору: git
add+commit, cp jsonl, append в index.json, аудит `checkpoint.create`.
Работает и для активной, и для неактивной сессии — ничего не
перезапускается (одна итерация 5s-цикла). Идемпотентность: пустой diff +
тот же jsonl → коммит всё равно создаётся (`--allow-empty`, anchor
разговора важнее дельты файлов).

**Авто-чекпоинты (событийные, БЕЗ таймеров):**
- перед каждым switch (label `auto: before switch → <name>`), best-effort —
  сбой чекпоинта не блокирует switch;
- перед каждым rewind (label `auto: before rewind`) — rewind сам всегда
  обратим; здесь сбой БЛОКИРУЕТ rewind (без страховки не откатываем).
- ~~перед delete сессии~~ — НЕ строим: delete и так переносит весь каталог
  в `~/work/.trash/` целиком, дублировать нечего.

### rewind — исполняет супервизор

`POST /sessions/:id/checkpoints/:cid/rewind`:

1. cp-api валидирует (формат cid, чекпоинт есть в index.json),
   пишет запрос-файл `~/.claude/run/session-task.json`
   `{"id":…,"action":"rewind","name":…,"checkpoint":…}`.
2. Супервизор entrypoint (тот же 5s-цикл, что switch):
   - авто-чекпоинт pre-rewind (сбой → отказ всей операции);
   - если сессия активна — ПАРКУЕТ pane (`respawn-window -k "sleep 600"`)
     ДО восстановления файлов: умирающий claude не может дописать jsonl
     или файлы ПОСЛЕ реставрации;
   - `git reset --hard <commit>` + `git clean -fd` (untracked-файлы,
     родившиеся после чекпоинта, уходят — pre-rewind-чекпоинт их хранит;
     ignored-мусор не трогается — без `-x`);
   - копирует `conv/<id>.jsonl` поверх исходного jsonl (+`touch` — чтобы
     `--continue` подхватил именно его);
   - если сессия активна — `launch_claude <dir> switch` → `--continue`
     поднимает восстановленный разговор; readiness-механика M5.7
     (session-state.json, 🟡→🟢) работает без изменений;
   - result-файл, cp-api поллит ≤90 с (тот же контракт, что switch).
3. Rewind НЕАКТИВНОЙ сессии — те же шаги без respawn (вступает в силу
   при следующем switch). Дешёво и безопасно.
4. Telegram-паритет: `session-ctl checkpoints [name]` / `session-ctl
   checkpoint [label]` / `session-ctl rewind <id> [name]` — бот делает
   то же по просьбе в чате; suicide-rewind безопасен (исполнитель —
   супервизор).

### список / лимиты

- `GET /sessions/:id/checkpoints` — index.json (cp-api читает напрямую,
  newest first).
- Ретенция: cap N=20 чекпоинтов на сессию (`CHECKPOINT_CAP` env);
  при переполнении удаляется самый старый АВТО-чекпоинт (ручные живут до
  явного удаления или до cap×2). `DELETE .../checkpoints/:cid` — удаляет
  запись + conv-файл (исполняет супервизор; git-объекты чистит `git gc
  --auto` на каждом create — событийно, НЕ периодически).

## Mini App

В строке сессии (SessionsManager) — кнопка «🕑 чекпоинты» → экран таймлайна:

- список: метка, время, auto/ручной, активный бейдж «← вы здесь» у
  последнего применённого;
- «＋ Чекпоинт» с опциональной меткой — мгновенно, без подтверждения
  (операция безопасна);
- «⏪ Откатить» — двухтапный confirm (паттерн M5.7; window.confirm в
  webview не работает), текст предупреждения: «файлы проекта и разговор
  вернутся к состоянию чекпоинта; текущее состояние будет сохранено
  авто-чекпоинтом»; для активной сессии — предупреждение об interrupt +
  🟡 readiness-поллинг как у switch.

## Безопасность / инварианты

- Всё внутри границы тенанта; ни одного нового root-компонента; супервизор
  уже исполняет switch — rewind тот же класс операции (ADR-004).
- Аудит: `checkpoint.create` / `checkpoint.rewind` / `checkpoint.delete`.
- Ничего не уничтожается без следа: pre-rewind авто-чекпоинт всегда;
  conv-копии и git-объекты живут в `~/.claude/checkpoints/`.
- Нулевые рекуррентные процессы: все триггеры событийные (create/switch/
  rewind/delete), таймеров и cron нет, LLM не вызывается.
- Откат фичи: убрать кнопки Mini App + routes; данные в
  `~/.claude/checkpoints/` инертны.

Build в репо: entrypoint (checkpoint-блок + TASK_REQ в супервизор-цикле +
авто-чекпоинт в switch), `session-ctl` (checkpoints/checkpoint/rewind),
cp-api checkpoint-routes в `session-routes.ts`, miniapp CheckpointsPanel
(🕑 на строках сессий), `install/m5.8-accept.mjs`. Self-test механики
git-снапшота (13 проверок: excludes, gitlink, reset+clean, undo, ретенция)
— ALL PASS; typecheck api+miniapp OK, vite build OK, bash -n OK.

1. **Image rebuild + pod restart** (исполнитель задач живёт в entrypoint;
   убивает текущую сессию бота — в конце рабочего дня):
   ```
   bash /home/vitaliy/work/fleet-platform/runtime/install/m2.1-build-image.sh
   systemctl restart claude-pod@vitaliy
   ```
2. **cp-api**: `podman restart cp-api`.
3. **Mini App**: `cp -a .../apps/miniapp/dist/. /var/www/miniapp/dist/`.
   (До ребилда образа кнопки чекпоинтов отвечают 504 — супервизор старого
   образа не читает task-файл; деградация мягкая.)
4. **Приёмка, фаза A** (после ребилда; безопасна — pane не трогает):
   ```
   podman run --rm --network host --secret cp_bot_token \
     -v /home/vitaliy/work/fleet-platform/control-plane:/cp:ro -w /cp \
     -e BOT_TOKEN_FILE=/run/secrets/cp_bot_token \
     docker.io/library/node:22-alpine node install/m5.8-accept.mjs
   ```
5. **Приёмка, фаза B** (та же команда + `-e DO_REWIND=1`; ДЕСТРУКТИВНО —
   респавнит pane клода; гонять, когда бот idle).
6. Ручной тест: 🕑 в Mini App (создать → откатить → 🟡→🟢), `session-ctl
   checkpoint`/`rewind` из чата.

**Rollback (одна команда на слой):** `git revert <commit>` + повтор шага
слоя. Данные в `~/.claude/checkpoints/` инертны.

## Открытые вопросы — РЕШЕНЫ (Vitaliy, msg 2931, 2026-06-12)

1. **Cap ретенции = 20** (env `CHECKPOINT_CAP`, ручные до 2×cap).
2. **`git clean -fd` при rewind — ДА**: файлы, созданные после чекпоинта,
   удаляются (pre-rewind авто-чекпоинт их сохраняет). Без `-x` —
   ignored-мусор (node_modules и т.п.) не трогается. Нюанс: вложенный
   git-репозиторий, созданный ПОСЛЕ чекпоинта, `clean -fd` не удаляет
   (git не чистит чужие репо без `-ff`) — это безопаснее, оставляем.
3. **Default-сессия — включена**, глобальный excludesFile теневого репо:
   `.trash/ node_modules/ dist/ .venv/ .cache/ __pycache__/ *.log`;
   вложенные репо — gitlink (ограничение выше, текст в UI есть).
