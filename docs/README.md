# Миграция: Genesis → целевая архитектура

Этот раздел описывает, как перевести **уже работающий на удалённом сервере прототип «Genesis»** (`/opt/workspace`) к целевой архитектуре **без простоев и резких перезапусков ботов для живых пользователей**.

> Папка `migration/` самодостаточна: и механика перехода (`00`–`05`), и план разработки нового функционала (`06`–`13`) описаны здесь полностью. Ничего другого на сервер копировать не нужно.

## Зафиксированные решения по миграции
- **Топология перехода: in-place.** Перестраиваем тот же сервер постепенно. Пользователи переводятся на новый рантайм **по одному**; ещё не мигрированные продолжают работать на старом стеке рядом. Никакой массовой остановки.
- **Сначала стабилизация (Фаза 0), потом архитектурная миграция.** Текущие проблемы прод-стека (отвал TG-плагина при `claude -p`, случайные рестарты) чинятся хотфиксами на действующем стеке **до** начала перевода на Podman/onecli/LiteLLM. Это останавливает «кровотечение» и даёт стабильную базу для миграции.

## Принципы бесшовности
- **Strangler-подход.** Новый рантайм (контейнер на пользователя) поднимается рядом со старым `claude-tg@<user>.service`; переключение — атомарная передача bot-токена. Старое не трогаем, пока новое не подтверждено здоровым.
- **Один и тот же bot-токен** у пользователя до и после перехода → для пользователя в Telegram «тот же бот», без пересоздания, без потери чата.
- **Перенос контекста сессии.** Текущий лог сессии и память переносятся, чтобы помощник «помнил» прошлое после перевода.
- **Окно переключения — секунды.** Telegram допускает ровно одного потребителя `getUpdates` на токен; cutover = «погасить старый поллер → поднять новый» за короткое окно (входящие в этот момент Telegram буферизует и доставит новому поллеру).
- **Мгновенный откат.** На каждом шаге — возможность вернуть пользователя на старый сервис, пока тот не выведен из эксплуатации.

- Изоляция (+ жизненный цикл/эластичные лимиты) → [08 — Рантайм Podman и гейтвеи](08-runtime-and-gateways.md)
- Доступ к модели/fair-use → [08 — Рантайм Podman и гейтвеи](08-runtime-and-gateways.md)
- Секреты (платформенные/пользовательские) → [08 — Рантайм Podman и гейтвеи](08-runtime-and-gateways.md), [04 — Миграция секретов и данных](04-secrets-and-data-migration.md)
- Безопасность (6 уровней, автономность) → [09 — Стек безопасности](09-security-stack.md)
- Авторинг + закрытие пробелов паритета → [10 — Авторинг: Mini App + web-IDE](10-authoring-miniapp-ide.md)
- Модель данных (бэкфилл Postgres) → [07 — Control plane](07-control-plane.md)
