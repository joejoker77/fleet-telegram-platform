# M5.11 — Live tool stream: пошаговая активность бота в LiveActivity

Запрос Vitaliy (2026-06-12, msg 3008): «я хочу видеть запуск всех субагентов,
выполнение кода… всё, что делает агент — пошагово и в реальном времени; токены /
модель / кеш — в самом конце». Pilot: vitaliy only (как весь M1+).

## Механизм — один новый хук, ноль новых поверхностей

Claude Code зовёт `PreToolUse`-хуки перед КАЖДЫМ вызовом инструмента (включая
вызовы внутри субагентов — они работают в том же харнессе). Новый хук
`tool-activity-hook.mjs` (в образе, рядом с metering-хуком) эмитит компактное
аудит-событие `tool.use` `{tool, summary}` в сокет коллектора — дальше работает
ровно существующий конвейер M5.4: WORM + audit_index + Redis `live:<userId>`
(атрибуция actor→userId уже починена в dbfab16) + ws `/live` → Mini App.

- `summary` — одна человекочитаемая строка на инструмент: Bash → команда
  (обрезана до 200), Task/Agent → subagent_type + описание, Edit/Write/Read →
  путь, Skill → имя+аргументы, Grep/Glob → паттерн, Web* → url/query,
  MCP-тулы → первое строковое поле. Никакого LLM.
- Хук на латентности каждого тула: fire-and-forget (пишет в сокет и уходит,
  ack не ждёт), stdout пустой и exit 0 ВСЕГДА (stdout PreToolUse-хука может
  нести permission-решение — мы принципиально не печатаем ничего).
- «Токены в самом конце» — уже так: metering Stop-хук шлёт `usage.turn` по
  завершении хода (model + in/out + cache read/write уже в payload); UI теперь
  рендерит это одной строкой.

## Решения

1. **tool.use = полноценная аудит-запись** (WORM + PG + live), не отдельный
   «эфемерный» канал. Единый конвейер, и тул-уровневый журнал сам по себе
   ценен для M4-аудита. Цена: ~1 запись на вызов инструмента (сотни байт);
   объём приемлемый, файлы и так ротируются по дню.
2. **PreToolUse, не PostToolUse** — поток в реальном времени («что запускается»),
   а не пост-фактум. Статус/длительность шага — возможная добавка позже
   (PostToolUse), на MVP не нужна.
3. **Латентность**: +~50–80 мс node-старта на каждый вызов инструмента.
   Осознанная цена пилота; если станет заметно — заменить на компилируемый
   бинарь или persistent-демон НЕ предлагаем (демон = новый процесс в поде),
   сперва замерить.
4. Гранулярность «шаг воркфлоу» = вызов инструмента (Task/Skill/Bash…) — это
   и есть шаги оркестратора. Отдельных событий из тела slash-команды нет.

## UI (LiveActivity)

- `tool.use`: иконка по инструменту (🤖 Task, 🖥 Bash, ✏️ Edit/Write, 📖 Read,
  🔎 Grep/Glob, 🧩 Skill, 🌐 Web, 🔌 mcp__*) + всегда видимая строка
  `Tool · summary`; полный payload — по тапу, как раньше.
- `usage.turn`: строка `model · in N / out N · cache Nr + Nw` — итог хода.
- `fs.*`: показываем путь.

## Деплой (по слоям)

1. **Mini App** — dist copy (можно сразу; новые виды событий просто не идут
   до рестарта пода).
2. **Хук в образ** — едет с уже запланированным M5.8-ребилдом
   (`m2.1-build-image.sh`) + `systemctl restart claude-pod@vitaliy`.
3. **Wiring в settings.json** — `install/m5.11-live-tool-stream.sh apply`
   (root, до рестарта пода): ADR-003-флоу — пауза guard → jq-вставка
   PreToolUse-entry (без matcher = все тулы) → commit в git HEAD `~/.claude`
   → `agentshield-settings-rebaseline` → re-arm. Хуки читаются на старте
   claude → эффект после рестарта пода.

## Rollback

- `install/m5.11-live-tool-stream.sh rollback` (убирает entry тем же флоу) +
  рестарт пода. Хук-скрипт в образе инертен без wiring.
- UI: revert + dist copy. События tool.use в WORM остаются (журнал append-only,
  это by design).

## Приёмка

1. После рестарта пода: открыть 📡 Live, дать боту задачу с инструментами
   (например `/fact-quest <тема>`) — в ленте по мере выполнения появляются
   tool.use-строки (Task с subagent_type, Bash-команды, Read/Edit пути),
   в конце хода — usage.turn с моделью/токенами/кешем.
2. Латентность: ход бота не деградирует заметно (хук fire-and-forget).
3. Rollback-скрипт возвращает settings.json к прежнему HEAD-состоянию.
