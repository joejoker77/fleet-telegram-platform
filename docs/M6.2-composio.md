# M6.2 — Composio: ключ в OneCLI, key-less хелперы, callback в cp-api

Второй инкремент M6 (`11-integrations.md`). В прототипе Composio-ключ лежал
инлайн в `.mcp.json` (`headers.x-api-key`, doc 04), а callback жил отдельным
`composio_callback.py`, который инжектил [SYSTEM]-сообщение в tmux. В поде
сейчас composio МЁРТВ: `.mcp.json` указывает на несуществующий stdio-бридж
`/usr/local/bin/composio-mcp-bridge`.

Новая схема: ключ только в OneCLI vault (инжекция `x-api-key` на egress),
хелперы в образе работают **без ключа**, callback — публичный эндпоинт cp-api
с уведомлением в чат через main-bot `sendMessage` (паттерн approvals, M5.4b).

## Решения и факты под ними

- **Hosted auth (Connect Link), не `initiate()`**: legacy
  `POST /api/v3/connected_accounts` для Composio-managed OAuth отключается
  (400) 2026-07-03 для всех организаций. Используем
  `POST /api/v3.1/connected_accounts/link` — он же отдаёт `redirect_url`.
- **Два секрета с одним значением**: REST живёт на `backend.composio.dev`,
  tool-router MCP-сессии могут отдаваться на `mcp.composio.dev` — у прокси
  точные host-паттерны (как git-PAT/exa), без wildcard-экспериментов.
- **Tool-router session вместо статичной MCP-станзы**:
  `POST /api/v3.1/tool_router/session {user_id, manage_connections:{enable}}`
  → `{session_id, mcp:{url}}`; URL кладётся в `~/work/.mcp.json` (http, без
  headers — ключ инжектится). Это даёт те же 6 мета-тулов
  (SEARCH_TOOLS/MANAGE_CONNECTIONS/…), что в прототипе.
- **uid в callback_url**: `composio-connect` сам встраивает
  `?uid=<chat_id>&toolkit=<slug>` в callback; Composio дописывает
  `status` и `connected_account_id`. Эндпоинт публичный и **ничего не
  меняет** — только страница «вернитесь в Telegram», sendMessage и audit;
  подделка uid даёт максимум ложное уведомление, ограничено rate-limit'ом
  5/час на uid.

## Состав

| Компонент | Файл |
|---|---|
| Vault-скрипт (operator) | `runtime/install/m6.2-composio-vault.sh` (+`-rollback.sh`) |
| Хелпер Connect Link | `runtime/image/platform/bin/composio-connect` (в образ как `/usr/local/bin/composio-connect`) |
| Хелпер tool-router | `runtime/image/platform/bin/composio-session` |
| Callback-роут | `control-plane/apps/api/src/integration-routes.ts` (`GET /integrations/composio/callback`) |
| Приёмка роута | `control-plane/install/m6.2-accept.mjs` |

Аудит-события: `integration.connected` / `integration.connect_failed`
(payload: provider, toolkit, connectedAccountId).

## Деплой (порядок)

1. **Bot:** rebuild cp-api ts → **Operator:** `podman restart cp-api`;
   приёмка роута:
   ```bash
   podman run --rm --network host \
     -v /home/vitaliy/work/fleet-platform/control-plane:/cp:ro -w /cp \
     docker.io/library/node:22-alpine node install/m6.2-accept.mjs
   ```
2. **Operator:** ключ в vault (значение — `headers.x-api-key` из прототипного
   `.mcp.json` в старом workspace; бот его прочитать не может):
   ```bash
   bash /home/vitaliy/work/fleet-platform/runtime/install/m6.2-composio-vault.sh
   ```
3. **Operator:** rebuild образа пода + рестарт (хелперы в образе):
   тот же цикл, что для M5.x image-инкрементов.
4. **Bot (в поде):** probe `curl …/api/v3/toolkits` → 200;
   `composio-session --user-id 2112420187` → MCP URL → `~/work/.mcp.json`
   (заменить мёртвую stdio-станзу); после следующего рестарта сессии
   мета-тулы видны.

Шаги 1 и 2–3 независимы; финальная проверка — только после всех.

## Приёмка

- `m6.2-accept.mjs` → OK (роут, html, валидация, UX-правило «не говорим
  Composio/OAuth/MCP»).
- С пода: `composio-connect --toolkit gmail --user-id 2112420187` печатает
  `https://connect.composio.dev/link/…`.
- Клик по ссылке → OAuth → браузер на callback-странице «✅ Gmail подключён»,
  в чате уведомление, в audit — `integration.connected`. (Это уже M6.4 e2e.)
